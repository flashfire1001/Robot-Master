### 1.物理信号

>   CAN接线方式

每个设备引出两根线，一根是 CAN_H ，一根是 CAN_L （当然也有单线 CAN 但速度低我们不考虑使用）； 不同设备的 CAN_H 接到一起， CAN_L 接到一起CAN_H 与 CAN_L 通过 120Ohm 电阻连接在一起，防止总线上传输的高频信号存在反射振铃效应导致信号不稳定、寄生电容导致信号响应速度变慢等情况（感兴趣可以看电磁场相关的理论）

>   信号电平格式

差分信号传输 ：$V_{diff}= V_h - V_l$

0信号-显性-Vdiff= 3.5 –1.5 = 2V;

1信号-隐形-Vdiff=2.5-2.5 = 0V;

### 2.链路传输

####几种概念与机制

-   CAN ID

一帧信息的标识符,指明是谁发的

在计算机网络中的大多数协议里，地址与一个设备或一个终端完全绑定且一定范畴内一一对应；但 CAN 设备不存在一个固定的地址，而是以 ID 加以区分不同的帧的来源或目标
比如， IP 地址可以在一个网络内唯一指定一个网络设备（不考虑伪造等非法的网络攻击或IP 冲突等错误情况）；但 CAN ID 不可以，它只对它发送的报文负责，设备可以发 ID 为0x201 的报文，也可以发 ID 为 0x202 的报文，每个报文也可以指定不同的信息

-   冲突检测和仲裁

众所周知，一根物理意义的导线上不可能同时是高电平和低电平，一条传统通信方式的链路上也不可能同时传输0 和 1 ，因此需要一定的冲突处理机制:	

所以，当链路上存在设备想发送 0 的同时又有设备发送 1 的时候，链路中表现为 0 ，因为 0 是显性电平此时，想发送 1 的设备发现，链路怎么变成 0 了？原来是有人也要发消息，那我沉默先等待.

-   误码效验

差分信号在物理层上一定程度上解决了接口间信道上传输过程中环境噪声问题，而误码校验在链路层上减少了硬件偶然错误的信息编码被解析利用，以及仍可能存在的强干扰环境噪声导致信道电压波动很大改变电平的风险—它采用CRC algorithm.

#### 实际情况:帧的处理

在计算机网络上一般而言物理层叫信号，链路层叫帧，网络层叫报文，传输层叫流，再往上叫数据，当然也可以统一都叫数据，我这里把帧这个名字拿来用了

帧的类别:数据帧,遥控帧,错误帧,过载帧,侦间隔

>   数据帧发送数据。细分两种，一种是标准数据帧，一种是扩展数据帧，区别在于它们的CAN ID 长度不同
>
>   遥控帧请求其他设备给他(发出设备)控制指令(数据帧) ，该帧的 ID 表明请求该 ID 对应设备的数据，也有标准遥控帧和扩展遥控帧的两种，区别也是在于它们的 CAN ID 长度不同

>   帧间隔:在前两个主动帧之间发送 错误帧(出错了) 过载帧(忙)

### 4.电机控制具体CAN信号:

以下是基于 **数据段内自定义标识符** 的电机控制数据段字节分配示例，结合CAN总线协议和实际应用场景设计：

------

#### **数据段字节分配（8字节）**

| **字节序号** | **功能**           | **内容说明**                                                 | **数据格式与示例值**                                      |
| ------------ | ------------------ | ------------------------------------------------------------ | --------------------------------------------------------- |
| **0**        | **目标电调标识符** | 指定接收指令的电调编号（自定义逻辑，如`0x01`=电调1，`0x02`=电调2）。 | `0x01`（电调1）                                           |
| **1-2**      | **目标转速**       | 电机目标转速（16位有符号整数，分辨率=0.5 RPM，范围-32768~32767 RPM）。 | `0x1F 0x40` → 5000 RPM（解析公式：`0x1F40 × 0.5 = 5000`） |
| **3**        | **方向控制**       | 正转/反转/停止（1字节枚举值）。                              | `0x01`=正转，`0x02`=反转，`0x00`=停止                     |
| **4**        | **使能信号**       | 使能电机驱动器（1字节标志位）。                              | `0x01`=使能，`0x00`=禁用                                  |
| **5-6**      | **目标电流**       | 电机目标电流（16位有符号整数，分辨率=0.1A，范围-3276.8~3276.8 A）。 | `0x10 0x00` → 16.0A（解析公式：`0x1000 × 0.1 = 16.0`）    |
| **7**        | **校验和**         | 前7字节的累加和取低8位（用于数据完整性校验）。               | `0x3A`（假设前7字节累加和为`0x003A`）                     |

------

#### **完整数据段示例**

```plaintext
数据段（8字节）： [0x01, 0x1F, 0x40, 0x01, 0x01, 0x10, 0x00, 0x3A]
```

-   **第0字节**：`0x01` → 目标电调1。
-   **第1-2字节**：`0x1F 0x40` → 转速5000 RPM。
-   **第3字节**：`0x01` → 正转。
-   **第4字节**：`0x01` → 使能电机。
-   **第5-6字节**：`0x10 0x00` → 电流16.0A。
-   **第7字节**：`0x3A` → 校验和。

------

#### **关键设计说明**

##### **1. 目标电调标识符（第0字节）**

-   **作用**：通过数据段内的自定义标识符指定接收指令的电调，而非依赖CAN仲裁段ID。
-   优势
    -   单片机通过广播发送指令（如CAN ID=0x200），多个电调同时接收。
    -   电调仅处理数据段中标识符匹配自身的帧（如电调1仅响应`0x01`）。

##### **2. 参数编码规则**

-   **低字节优先（Little-Endian）**：多字节参数按低字节在前传输。
     例如：转速5000 RPM → 高字节`0x1F`（240）先传输，低字节`0x40`（64）后传输。
-   分辨率定义
    -   转速：`0.5 RPM/bit` → 16位范围覆盖±32767 RPM。
    -   电流：`0.1A/bit` → 16位范围覆盖±3276.8A。

##### **3. 校验机制**

-   **累加和校验**：前7字节累加后取低8位，接收端重新计算并比对。
-   **扩展方案**：可替换为CRC-8或CRC-16算法提升可靠性。

------

#### **实际应用流程**

1.  **单片机发送控制帧**：
    -   **CAN ID**：`0x200`（广播控制指令）。
    -   **数据段**：`[0x01, 0x1F, 0x40, 0x01, 0x01, 0x10, 0x00, 0x3A]`。
2.  **电调1处理流程**：
    -   **过滤标识符**：检查数据段第0字节是否为`0x01`。
    -   **解析参数**：提取转速、方向、电流等指令。
    -   **执行动作**：驱动电机以5000 RPM正转，电流限制16.0A。
3.  **反馈机制**：
    -   电调1通过自身CAN ID（如`0x201`）发送状态帧，包含实际转速、电流等数据。

------

通过 **数据段内自定义标识符**（如第0字节）与 **CAN仲裁段ID** 的配合，可实现以下功能：

1.  **一对多控制**：单片机广播指令，多个电调通过数据段标识符响应。
2.  **灵活扩展**：通过调整标识符和参数编码，支持不同电机或设备。
3.  **高可靠性**：校验机制确保数据完整性，避免误操作。
